# Contributing

Start with a reproducible problem or a missing user workflow. Keep skills small and composable; check existing triggers before adding a new name.

Preserve portable SKILL.md frontmatter, relative references, clear inputs, ordered methods, stop conditions and observable completion. Keep host-specific installation information in documentation rather than the core.

For code changes, use a failing behavioural test before implementation and check the affected workflow plus regressions. Never treat a mock process as native agent execution. Provide public-safe examples and inspectable evidence, including failures.

Do not commit credentials, private transcripts, home paths, copied books or unknown-licence assets. Preserve source attribution and third-party notices.

Run `python3 scripts/verify.py` on an unchanged release. Edits intentionally invalidate its published hashes; show your diff and targeted check results for review. Release manifests are reissued by the publisher after review, not silently resealed by the consumer tool.
