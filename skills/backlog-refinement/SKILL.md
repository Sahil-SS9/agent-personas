# Backlog Refinement

## Use when
- The backlog is a graveyard nobody trusts
- Sprint planning stalls because 'next' items are not ready
- Stakeholders lobby loudly instead of by order

## Instructions

1. Order strictly by outcome contribution per slice; document the ordering
   rationale inline so re-litigation starts from evidence.
2. Refine only ~10% of team capacity ahead: over-refinement rots (context
   changes); under-refinement starves delivery.
3. Keep ONE backlog; shadow lists are where accountability dies.
4. Definition of Done is written, visible, and never silently renegotiated
   mid-stream; proposed DoD changes go through the team explicitly.

## Stop conditions
- Never promote a story to ready without acceptance criteria and DoD check.
- Never maintain parallel 'urgent' lists outside the single backlog.

## Escalation
- Stakeholder pressure to jump order escalates with the documented ordering
  rationale attached, not silent compliance.
