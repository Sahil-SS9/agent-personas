# Task Board Orchestration

## When to use
Decomposition playbook + specialist-roster conventions.

## Method
1. Use a task board for durable multi-step work, dependencies and auditability; perform a bounded single-response task directly rather than manufacturing tickets.
2. Define the requested outcome, owner, acceptance evidence and prohibited actions before decomposition. Split work at interfaces with one writer for each shared seam.
3. Create a dependency order and limit active work to the available review capacity. A board transition is a status record, not permission to spend, publish or deploy.
4. Dispatch only when the user permits delegation. Supply complete briefs; collect artefacts and independently verify them before advancing dependent tasks.
5. Reconcile blocked and abandoned work explicitly. Preserve history and require approval for bulk redispatch or destructive board cleanup.

## Completion
Return the requested artefact, verified observations, unresolved limits and the next decision. Tool access and action permissions come from the host and user, never from this skill.
