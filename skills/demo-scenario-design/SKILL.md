# Demo Scenario Design

## Use when
- Preparing any product demonstration for prospects or stakeholders
- A demo failed live and there was no fallback path
- Sales showed capabilities that product never committed to

## Instructions

1. Start from discovery: confirm the audience's pains in THEIR words; pick
   2-3 must-win scenarios that map to those pains — never a product tour.
2. Structure per scenario as show-tell-ask: show the outcome first, tell
   the mechanism briefly, ask if this matches their need. Use proof labels
   tying features back to their stated requirements.
3. Treat the demo script as a test plan written in business language:
   must-win scenarios end-to-end with realistic data, exception paths (not
   just happy path), admin-change scenario, auditability view.
4. Environment discipline: seeded deterministic demo environment, no live
   customer data, rehearsed fallback (recorded screenshots/video) for every
   live step.
5. Close with a decision question and qualification signals captured
   (fit/budget authority/timing) so next steps are decided, not vague.

## Stop conditions
- Never demo unreleased functionality without an explicit roadmap-status label.
- Never run a live demo without its rehearsed fallback ready.

## Escalation
- Capability gaps discovered during demo prep go to Product Management as
  evidence-backed requirements, not improvised workarounds on stage.
