# Broad reference and component landscape

Sources: F01–F08 plus F09–F14 in the batch ledger. This is a refreshable starting set, not an approved-install list or popularity ranking.

## Distinct source roles
- 21st.dev (F09): multi-author discovery registry across design systems, marketing, product, forms, motion and other categories. Include it in relevant searches; inspect the original author's component, not only the registry preview. Do not treat it as one framework or licence.
- React Bits (F10): animated/interactive visual material. Primary site extraction failed in this pass; the official GitHub repository was accessible. Review exact component dependencies, rights and reduced-motion behaviour before use.
- Magic UI (F11) and Aceternity UI (F12): expressive marketing components and motion. Both offer material in the React/Tailwind ecosystem; paid/free distinctions must be checked. They widen visual vocabulary but do not alone escape shadcn-like defaults.
- Base UI (F13): unstyled React primitives, supports custom styling rather than prescribing an aesthetic. Its site states MIT licensing. Component-level behavioural checks still apply.
- React Aria (F14): accessible behaviour and custom-style composition. Official documentation describes adaptive interaction and internationalisation. These are vendor capabilities to verify in the actual implementation, not blanket compliance evidence.
- Beautiful UI, beUI, Rare UI and Transitions.dev remain conditional sources, not default foundations.

## Go beyond this list
Inspect independent production sites, editorial layouts, identity systems and user-provided references as visual sources. For non-React projects, search the actual framework's maintained ecosystem and native HTML/CSS before proposing migration. Established domain systems can be appropriate; newness is not a requirement. Custom layout and typography may deliver more distinctive results than additional packages.

## Currentness protocol
For each task, search recent releases/changelogs and the registry for additional relevant candidates. Record the observation date, original docs/repository, relevant version/revision, licence status and why it fits. Do not label a library recently popular from memory or registry views alone. A registry listing is discovery evidence; maintenance, compatibility and production readiness are separate checks.

## Source combination rule
Choose references for the desired design, then compatible implementation material. Several sources are allowed; competing global resets, token systems, focus primitives and animation ownership require reconciliation. Prefer one coherent behavioural foundation with deliberate local adaptations. Never mix libraries merely to satisfy a diversity quota.
