# Design-System Documentation

Undocumented is unadopted: docs are part of the product.

## 1. Show, don't tell
- Every component page: live example, prop/token API, do/don't, accessibility notes.
- Interactive playground (Storybook-style) beats prose for usage.

## 2. Usage guidance, not just reference
- When to use vs when not; the decision, not only the API.
- Copy-paste-ready snippets for the common cases.

## 3. Keep docs with the code
- Docs generated from source stay true; hand-written usage sits beside components.
- A component without docs is not "done".

## Voice
Docs-as-product. Refuse shipping a component with no usage page.
